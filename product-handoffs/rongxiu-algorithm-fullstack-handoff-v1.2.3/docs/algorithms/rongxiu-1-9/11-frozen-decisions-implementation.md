## R1：匿名来源与叙述归属

### 后端权威结构

获准进入总信的每条素材使用 [`approved-material.json`](schemas/approved-material.json)：

```json
{
  "sourceType": "STORY",
  "sourceRef": "backend-only-reference",
  "authorLabel": "投稿者A",
  "materialLabel": "素材A-01",
  "narrativeAttribution": {
    "experienceSubject": "AUTHOR",
    "basis": "FIRSTHAND"
  },
  "text": "已获准素材"
}
```

固定枚举：

- `sourceType`: `STORY | WISH | CAPTION`
- `narrativeAttribution.experienceSubject`: `AUTHOR | RECIPIENT | THIRD_PARTY | UNKNOWN`
- `narrativeAttribution.basis`: `FIRSTHAND | REPORTED | OPINION_OR_WISH | UNKNOWN`
- 可选 `speakerLabel`、`experiencerLabel` 只使用匿名显示值

`sourceType` 描述素材类型；`narrativeAttribution` 描述“谁讲、谁亲历以及依据”。两者不能合成一个枚举。投稿者是同事、亲友或本人，都不能单凭身份推定其亲历；无法确认时使用 `UNKNOWN`。

### 模型投影和审核回显

- 后端保存完整对象，用 `sourceRef` 关联真实原素材、用途许可、revision 和审批记录。
- 送模型前必须删除 `sourceRef`，只投影 `sourceType`、匿名作者/素材标签、叙述归属和已处理的 `text`。
- `authorLabel` 在项目内按作者稳定；`materialLabel` 在项目内逐素材唯一。同一作者的多条素材分别使用 `素材A-01`、`素材A-02` 等定位，不能只有一个“投稿者A”标签。
- 统筹审核页显示匿名标签；有权限的有效统筹可以经后端映射查看对应原素材。前端不得据匿名标签自行拼接内部 ID。
- 最终正文不得显示“投稿者A”“素材A-01”“本人回忆”等内部标签。
- 真实账号、手机号、`sourceRef`、审批人、审批状态、权限与内部来源 ID 只留后端。
- 匿名标签不等于正文脱敏。原文中的姓名、电话、地址或其他敏感信息仍须先经过输入与用途规则处理。
- 后端在生成前和采用时权威复核用途、审批、revision 和权限，不能信任客户端传来的“已批准”声明。

## R2：总信四种风格

### 枚举和前端名称

| `style` | 前端名称 |
|---|---|
| `natural_oral` | 自然口述 |
| `soft_literary` | 文辞柔美 |
| `calm_dignified` | 沉静大气 |
| `formal_sincere` | 郑重真诚 |

前端不得把名称替换为“温和文学、平静庄重、正式真挚”等近义版本。风格控件默认可见并预选“自然口述”；统筹无需先操作控件，可以直接点击“生成总信”。总信页面只有这一个主要任务时，不增加只能选一项的“加工动作”下拉框。

每个选项保留简短说明，并用同一条素材解释差异。以下示例只能用于 UI 说明，不是新的事实素材：

> 同一素材：有一次我没理解题目，您换了一个例子讲给我听。

| 风格 | 说明 | 同素材示例 |
|---|---|---|
| 自然口述 | 接近日常说话，直接、顺畅 | 有一次我没理解题目，您就换了个例子，又给我讲了一遍。 |
| 文辞柔美 | 句式更舒展，保持克制，不额外煽情 | 那一次，我没有理解题目，您换了一个例子，再为我讲解。 |
| 沉静大气 | 语气平稳，表达简洁有分量 | 有一次我没有理解题目，您换用另一个例子为我重新讲解。 |
| 郑重真诚 | 措辞正式、真挚，仍保留原事实 | 有一次我未能理解题目，您改用另一个例子向我重新讲解。 |

新接口统一使用小写 `style`。字段缺省时，后端明确补为 `natural_oral`；不能依赖 JSON Schema 的 `default` 自动填值。旧 `tone` 只留在兼容层，须先盘点真实历史枚举，再由算法确认逐值映射；不得猜测 `warm/plain/formal` 的对应关系。

统筹换风格重新生成时：

1. 保留已有人工修改稿及其 revision。
2. 新结果先作为独立 candidate 预览。
3. 用户明确采用后才产生新 revision。
4. 新 revision 产生时，旧确认失效并需要重新确认。

## R3：礼前邀请亲友共创

- 入口固定为统筹项目主页的“邀请亲友共创”；项目发起完成后仍可进入。
- 项目名称、截止日期等复用已有项目资料，不要求每次邀请重复填写。
- 先生成固定邀请模板；只有统筹已经写入实质寄语草稿时，才可以选择 07 AI 润色。
- 统筹预览后主动分享；首期支持微信好友/群分享和二维码海报，复制链接按实际渠道能力开放。
- 支持面向多人邀请，但不自动读取通讯录，不建设逐人群发。
- 首期允许转发普通共创入口。新进入者仍须登录、确认身份关系并经过投稿审核；转发不授予管理权，也不能读取他人私密投稿。
- 不提供“继续邀请”按钮不能阻止他人转发链接或二维码。若以后要求“仅指定受邀者可投稿”，须另建账号绑定邀请或准入审核，不能靠前端隐藏转发入口实现。
- 分享按钮点击不等于送达。可以统计有效进入、参与和投稿，不能仅凭分享动作显示“已送达”。
- 邀请荣休者查看或接收礼物是未来独立分支，不复用本期共创邀请路由。

## R4：个人祝福静态起笔

首期固定使用 6 条通用起笔，每次展示 3 条并支持“换一批”。模板正文、批次、点击保护和进入 04 的条件以 [`08-wish-starter.md`](08-wish-starter.md) 为准。

实施边界：

- 仅在正文为空或只有称呼时展示。
- 用户点击才填入可编辑草稿，不自动提交。
- 点击时重新读取正文，防止异步状态覆盖用户刚输入的内容。
- 换一批不改已经写好的草稿。
- 用户补充实际表达后才可进入 04；纯模板或只改标点不算实际表达。
- 首期不按人物关系维护多套模板，不长期记录每个人看过哪条，也不新增 HTTP 或模型路由。

## R5：留存、删除与撤回基线

### 建议期限

| 数据 | 产品建议口径 | 使用限制 |
|---|---|---|
| 未采用候选 | 最后活动后 7 天清理；用户明确删除时立即退出可用范围 | 清理后不得继续预览、采用或作为模型输入 |
| 临时转写音频 | 确认后尽快删除；失败恢复最长 24 小时 | 只适用于为转写临时保存的音频 |
| 原声祝福、明确保存的录音 | 作为用户原件管理 | 不得套用临时转写音频的删除期限 |
| 用户原件 | 按有效业务用途保存；普通删除建议提供 30 天恢复期 | 恢复期内也不得继续展示、生成或分享 |
| 审计元数据 | 建议 180 天 | 默认不含正文、音频和私信全文 |
| 已采用成品 | 随有效业务用途保存 | 仍受来源撤回和依赖失效约束 |

这些期限是产品建议基线。生产配置、隐私说明和对外承诺必须以 AI-D04 对实际数据库、对象存储、日志、第三方 Provider、备份与离线设备的验收结果为准。

### 撤回和依赖失效

1. 来源撤回用途后，系统立即停止采用、展示或分享依赖该来源且已经失去相应用途许可的候选和成品版本，并清理相关搜索/推荐索引。没有依赖该来源的内容不应全部失效。
2. 每次模型调用记录所有实际输入素材的 `sourceRef`、revision 和用途许可作为依赖。即使生成正文未逐字引用某条素材，也不能擅自解除依赖。
3. 用户可以分别清理候选、删除原件或撤回用途。正式内容走撤回/修订和依赖失效流程，不能把删除按钮等同于抹除审计事实。
4. 第三方删除失败可以重试，但本地不能因此无限保留正文副本。只保留执行删除所必需的任务标识、目标、状态和最小错误信息；第三方未确认完成前不得显示“已全部删除”。
5. 离线设备重新联网时，必须先同步并处理撤回事件，再恢复内容访问。离线许可有效期仍须 AI-D04 定案，不能承诺断网设备能被即时清除。
6. 普通删除进入恢复期后，内容虽然可由授权恢复流程找回，但不得继续展示、生成、分享或进入模型输入。

### Memory 与角色视图

- 关闭自动跨项目记忆和长期画像。
- 当前项目历史只有在用户显式选择且权限仍有效时才可复用；个人显式保存记忆不等于自动 Memory。
- 投稿者只查看本人内容及明确获准内容。
- 有效统筹可以人工查看已获准提交的待审稿，但待审稿不得进入 05 总信模型输入。
- 受礼者只查看用途允许的成品及获准展示的署名/来源入口，不查看内部审批日志。
- 共建者不需要长期 Memory；统筹者的项目内视图也不能绕过素材审批、用途和 revision 门禁。

## 上线前 AI-D04 必验项

以下项目没有通过真实环境验证前，交接材料只能标记为“待验收”：

- 上表各期限能否在数据库、对象存储、缓存、日志和备份中一致执行。
- 模型、ASR/TTS、对象存储等第三方是否提供可核验的删除状态及最长处理时间。
- 删除失败重试是否只保存最小任务状态，且不会留下可继续使用的正文或音频副本。
- 搜索、向量、缓存和派生索引是否随用途撤回同步失效。
- 离线设备重连时能否先应用撤回事件，离线许可最长有效期是多少。
- 30 天恢复、180 天审计等期限是否符合实际业务、法规和备份能力。

AI-D04 通过前，不得声称第三方数据已经彻底删除、备份可即时清除、离线设备可即时撤回，或把建议期限写成已批准的生产承诺。
