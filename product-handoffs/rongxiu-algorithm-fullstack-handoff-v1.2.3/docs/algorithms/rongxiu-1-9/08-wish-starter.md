# 08 祝福空输入起笔

> 产品决策基线：首期在个人祝福空白页提供静态起笔；不配置 Prompt、模型参数、Provider、App 或 Workflow。

## 能力卡

- `purpose`: `WISH`
- `mode`: `starter`（业务能力名）；实现方式固定为本地 `static`
- 输入：可选 `recipientTitle`、当前 `wish`、可选 `batchIndex`
- 输出：每批 3 条可点击的静态起笔
- 入口：参与者填写个人祝福的输入页
- 后续路由：用户补充实际表达后，才可进入 04 `WISH/polish`

本能力不是模型能力，不新增独立 HTTP 接口。前端可直接读取随版本发布的模板配置；如由后端下发，也只能返回同一份版本化静态配置，不能转发到模型 Provider。

## 静态模板 v1.2.3

首期准备 6 条通用起笔，分成两批，每批展示 3 条：

| `templateId` | `batchIndex` | 文案 |
|---|---:|---|
| `wish-01` | 0 | 想借这个机会，对您说…… |
| `wish-02` | 0 | 送上这份祝福，愿您…… |
| `wish-03` | 0 | 关于接下来的生活，我想祝您…… |
| `wish-04` | 1 | 此刻最想送给您的一句话是…… |
| `wish-05` | 1 | 有一份心意，想这样告诉您…… |
| `wish-06` | 1 | 写下这段话，我想表达的是…… |

后三条是按已批准的低风险原则补齐的实施文案，不代表产品逐字审批。若产品以后修改文案，必须更新 `templateVersion`，并重新核对不能预设辛苦、共同经历、人物关系或具体退休安排。

## 本地输入与返回

本地函数输入遵循 [`request-wish-starter.json`](schemas/request-wish-starter.json)：

`wish` 是必填字段；确认当前正文为空时也必须显式传入空字符串，避免把“未读取当前草稿”误当成“当前草稿为空”。

```json
{
  "recipientTitle": "李老师",
  "wish": "",
  "batchIndex": 0
}
```

`batchIndex` 缺省时由调用方补为 `0`。JSON Schema 的 `default` 只作说明，不能假设校验器会自动填值。

静态返回示例：

```json
{
  "mode": "static",
  "templateVersion": "v1.2.3",
  "batchIndex": 0,
  "items": [
    {"templateId": "wish-01", "text": "想借这个机会，对您说……"},
    {"templateId": "wish-02", "text": "送上这份祝福，愿您……"},
    {"templateId": "wish-03", "text": "关于接下来的生活，我想祝您……"}
  ]
}
```

这是本地模板返回，不使用统一 AI candidate 响应，也不产生 `promptVersion`、`modelVersion` 或模型 trace。

当 `wish` 已有实质正文时返回 `NOT_APPLICABLE` 并隐藏起笔；这不是模型失败，也不得覆盖当前草稿。

## 展示与编辑规则

1. 仅当祝福正文为空或只有当前表单中已知的称呼时展示起笔。称呼是独立字段时，`wish` 必须为空白；遗留页面把称呼放入正文时，只能匹配当前已知称呼及其相邻标点，不能用模糊规则把其他文字当成称呼删除。
2. 用户点击某条起笔时，再读取一次当前正文。正文已经出现实质内容时不得覆盖，并提示用户保留现有内容。
3. 点击只把该模板填入可编辑草稿，不提交、不发送、不进入已批准素材库。
4. “换一批”只切换 `batchIndex=0/1` 的候选列表，不修改已经写入输入框的内容。
5. 填入模板后先标记为 `TEMPLATE_ONLY`。只有用户在模板固定文字之外补充了实质表达，才转为 `USER_CONTENT`；只改空格、标点或换行仍视为纯模板。
6. `TEMPLATE_ONLY` 不得调用 04 润色，也不得作为有效投稿提交。进入 04 前重新校验正文含有用户补充的实质表达。
7. 首期不按关系维护多套模板，不长期记录某个人看过哪条模板，也不根据称呼推断共同经历。

## 验收断言

- 空白正文首次展示 `batchIndex=0` 的 3 条，换一批展示另外 3 条。
- 只有称呼时可以展示；已有实质正文时完全隐藏，点击竞态也不会覆盖正文。
- 点击模板只填入草稿；换一批、刷新候选都不改草稿。
- 纯模板或只改标点不能提交为有效祝福，也不能调用 04。
- 本能力没有任何模型调用、Provider 凭证、Dify App 或 Workflow 路由。
- 6 条文案不声称用户与荣休者有共同经历，也不预设“这些年辛苦了”等事实。
