## 结论

内容负责人回传的九项 Prompt 可以作为 `v1.2.0-content-review` 基线。它已经完成了 System/User 分层，事实只能来自输入、用户素材中的命令不获得权限、输出是 candidate、07/08 仍是原型等关键边界。

这份回传包暂时不能直接标记为全栈生产规格。需要先完成以下技术修正和门禁：

| 优先级 | 问题 | 影响 | 处理结论 |
|---|---|---|---|
| 阻断 | Manifest 的总信字段为 `approvedMaterials/body/editInstruction`，Schema 和 Prompt 使用 `materials/letterText/instruction` | 全栈路由和 Dify 变量会出现字段错配 | 统一业务请求字段为 `materials/letterText/instruction`；`approvedMaterials` 只作为旧名迁移记录，不再作为新配置字段 |
| 阻断 | 05 的业务素材包含 `sourceRef/authorLabel`，Prompt 又要求模型只看正文 | 原始数组直接传入会泄漏审计元数据，模型也可能输出来源信息 | 后端生成只含 `text` 的模型投影；原始素材和 `sourceRef` 仅后端留存 |
| 阻断 | 09 要求“只改指定局部”，但只有整篇正文和自然语言 instruction | Prompt 无法单独证明其他段落未被改写 | 保留为候选生成；全栈必须增加受保护区/差异比较。未具备稳定编辑范围时，09 不能进入生产验收 |
| 高 | 03、05、09 的正文上限与模型输出 token 预算未通过目标模型实测 | 可能截断或把不完整结果误判为成功 | 把输出上限分为契约安全上限和 Provider 可用预算；目标模型运行前不得声称长文通过 |
| 高 | 截图中的 Chatflow/Memory 布局不适合作为 1～9 默认配置 | 会把上一次会话带入下一次改写，污染候选 | 统一采用 Workflow；关闭 Memory、Knowledge、Vision 和工具调用（CAPTION 文本首版） |
| 中 | 04 的人工预期把“以后多出去走走，开心点”改成“开开心心地享受生活” | 改变了原句的具体建议，和“最小润色”断言不完全一致 | 修正回归参考为保留“多出去走走”，预期示例只作为语义参考，不做逐字金标准 |
| 中 | 07 的邀请对象和阶段仍未冻结 | 可能把礼前亲友共创和收礼者查看礼物混成同一场景 | 继续保持原型；默认优先固定模板，AI 入口等产品决策完成后再启用 |
| 中 | 08 与固定模板存在重复能力 | 增加模型调用和不可控输出，但不一定增加用户价值 | 默认先采用本地可编辑模板；只有需要结合上下文个性化时再启用 AI |

## 已确认可以接受的内容部分

- 01、02、03、04、06 的基本任务边界和输出合同清楚，可以进入 Prompt 版本冻结前的目标模型回归。
- 02 明确是文字 caption 整理，不把它误称为图片理解能力。
- 03 明确 title 不是事实来源，且保留视角、顺序和不确定性。
- 05 明确不同投稿人的第一人称不能合成一个集体“我”，也不能把个别承诺写成集体承诺。
- 07 明确 `recipientTitle` 不自动等于荣休受礼者，这个约束应保留。
- 08 明确非空实质祝福应路由到 `WISH/polish`，不能由 starter 覆盖原文。
- 09 明确结果只能是新 candidate，不能直接覆盖冻结版本。
- 回传包把“人工预期示例”和“实际模型结果”区分开，所有实际运行状态为 `NOT_RUN`，没有把未运行结果冒充通过。

## 需要保留的责任边界

内容负责人回传的是 Prompt 对和内容规则；算法端负责契约、版本、门禁和模型回归；全栈负责 Dify/Provider、路由、错误恢复、candidate 闭环和生产验收。Dify Studio 试跑成功只能证明 Workflow 能运行，不能证明生产接口和业务闭环完成。

## 本次修复内容

本次在仓库中完成以下修正：

1. 将 Dify manifest 的总信字段改为与 Schema 一致的 `materials`、`letterText`、`instruction`。
2. 将内容回传包登记为 `v1.2.0-content-review`，保留每项技术参数、Structured Output 和后端门禁。
3. 增加一份独立的 Dify 技术配置，明确 Workflow、无 Memory、结构化输出、模型参数记录和 1～9 的状态。
4. 增加 09 的后端差异校验门禁，不把“只改局部”错误地当成 Prompt 单独可保证的性质。
5. 在仓库增加 [`content-review-corrections-v1.2.0.jsonl`](./fixtures/content-review-corrections-v1.2.0.jsonl)，将祝福润色参考文本修正为保留原文的“多出去走走”；原始回传 ZIP 保持不覆盖，避免改写内容负责人的原始交付物。
