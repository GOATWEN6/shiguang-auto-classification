## 目前交付的是什么

本包状态是 `candidate/pre-human`。算法侧已经完成：

- 日常聊天和正式访谈的 HTTP 入口；
- 文字输入、PCM16 语音输入、流式 ASR、TTS 和服务端取消接口；真人播放中打断尚待设备验收；
- `InterviewPolicy` 的等待、承接、追问、换题、暂停和结束；
- Memory 候选抽取、连续原文来源检查、敏感性和权限边界；
- 故事草稿和基础画像两个相互独立的派生任务；
- `SemanticTurnProposal` Shadow 观察层。它只记录语义候选，不接管正式策略、不执行保存或删除；
- 健康检查、版本查询、幂等、错误状态和回滚说明。

当前运行结果仍属于测试会话候选：`canonicalWriteCapability=false`。这表示全栈可以展示 Memory 和画像，但不能把它们当成已经写入正式 `CanonicalMemory` 的长期数据。语音采用“独立 ASR + 文本模型 + 模块化 TTS”的链路；旧的端到端实时语音候选保持禁用，不属于本次接入路径。

## 全栈接入时要理解的主链

```text
文字/语音输入
  → ASR 与短文本规整
  → 本轮 evidence（保留来源）
  → InterviewPolicy 决定一个主要动作
  → 文本模型组织回复
  → TTS 播放；用户说话时 interrupt 取消旧生成
  → Memory 候选、故事草稿、画像草稿异步生成
  → view 返回候选、状态、来源和诊断
```

`InterviewPolicy` 是可信的行为边界：它决定是否进入访谈、是否继续、是否等待、是否换题和是否结束。LLM 可以理解复杂表达并给出 `SemanticTurnProposal`、`NarrativeCue` 和候选下一步，但这些候选不能直接改变模式、权限、保存、删除或分享。

Memory 也分两步：算法侧先从本轮证据提取候选并标出来源、时间和敏感性；后端再依据老人/家庭授权决定是否进入正式持久化。浏览器和模型都不能直接写 `CanonicalMemory`。

## 全栈按什么顺序接入

1. **Fake 接入**：用 `LOCAL_FAKE` 和 `examples/` 中的请求接通文字、NDJSON 事件、取消、结束和错误显示；真实音频播放、麦克风和打断在真实内部模式验证。
2. **查看结果**：接入 `/view`，分别展示本轮 Memory 候选、调用过的 Memory、故事草稿、画像草稿和 Shadow 诊断。`canonicalWriteCapability=false` 时必须显示“测试候选/未写入正式长期记忆”。
3. **真实内部接入**：算法负责人确认 build 和预算后，再使用 `REAL_INTERNAL`。浏览器只访问算法后端，不能携带豆包或其他 provider 的密钥。
4. **接入验收**：完成文字、语音、TTS、播放中打断、等待、暂停/恢复、换题、结束、重试和重复请求测试，并记录 requestId、buildId 和错误码。

## 这次全栈不需要承担的事情

- 不改写访谈产品原则和 `InterviewPolicy` 的行为边界；
- 不把 Shadow 候选接成第二个策略引擎；
- 不让 LLM 直接保存、删除、分享或改变家庭权限；
- 不把临时 Memory 直接迁移成生产 `CanonicalMemory`；
- 不把 provider 原始错误、密钥、内部主体 ID 和完整提示词返回浏览器。

## 交接验收口径

全栈完成下面几项后，反馈“接口接入完成”，但仍不等于算法正式发布：

- 页面能清楚显示连接、等待、回复、播放、打断、失败和恢复；
- 同一个幂等键重试不会产生重复轮次；
- 旧的 target 或旧 generation 的音频不会覆盖新回复；
- `view` 能区分候选 Memory、故事/画像草稿和正式持久化状态；
- 换题、暂停、不保存和结束会立即反映在页面；
- `/health` 不就绪时停止新的模型调用；
- 页面和日志中没有密钥、敏感原文泄露或 provider 原始异常堆栈。

## 三段式交付关系

当前是第一段：**仓库候选接口交接**。第二段由负责人体验当前真实模型，重点判断追问价值、Memory 准确性、故事/画像可用性、等待、TTS 和设备打断。已有 C1～C12 固定虚构案例及 6 轮定向复验证据，不需为迁移重复整批。第三段根据反馈修复、定向复验、冻结 build/合同/回滚提交，直接合并更新仓库。

本次分支还包含脱敏源码快照 `algorithm-handoff/sgx-source/`，方便全栈按路径查看和逐步迁移；快照不是把 SGX 工作树直接覆盖到分类仓库根目录，分类仓库原有代码保持不变。

本包可用于全栈并行开发，但不能提前标记为正式版本。所有结论都要绑定实际 `buildId` 和 `interviewPolicyVersion`，避免把历史公网测试、离线回放和本候选版本混在一起。

## 本轮真实体验补记：暂停、继续和换题

在负责人 C1～C12 真实 HTTP 体验中，发现两个会影响前端接入的行为：暂停后的输入被旧会话门禁提前拒绝；“这段先聊到这里，我们说说后来……”这样的自然表达没有识别为换题。算法侧已在 `pre-human-2026-10-15-pause-switch-v20` 修复并完成 5 轮定向真实复验：

- 自然换题返回 `SWITCH_TOPIC`，新主题保留为“后来在阳台种花”；
- 暂停返回 `PAUSE`，暂停态收到未明确继续的输入仍保持 `PAUSED`；
- 老人明确说“我休息好了，继续吧”后返回 `ACKNOWLEDGE`，会话恢复 `ACTIVE`；
- 暂停和暂停态拦截不播放 TTS，也不新增 Memory；
- `canonicalWriteCount=0`，仍未写入正式 `CanonicalMemory`。

详细原话、回复、等待、Memory、派生结果和状态见包内 [C1～C12 真实体验记录](./owner-c1-c12-real-smoke-report.md)。这组复验仍是固定虚构文本的真实模型调用，浏览器麦克风、真人听感、物理播放打断和故事/画像内容评审需要负责人在工作台继续完成。
