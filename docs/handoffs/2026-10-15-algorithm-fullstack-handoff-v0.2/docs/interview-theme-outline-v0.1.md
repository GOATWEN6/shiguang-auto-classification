# 拾光长河访谈主题优化大纲 v0.1

> 用途：把产品提供的“拾光长河分类 V3”整理成访谈算法可以使用的主题目录。
> 这是主题设计草案，不改变已经批准的老人主导、一次一问、可跳过、可暂停、访谈同意不等于保存同意等产品原则。

## 1. 先说明当前材料的范围

图片标题写的是“8 个主题”，但当前可读的表格只有 7 行。下面先保留这 7 行，并补充一个“人生转折与告别”候选主题作为第 8 行。第 8 行在负责人确认前标记为 `PROPOSED`，不会被策略层当作必须完成的任务。

主题目录是“可选择的地图”，不是要求老人按年龄顺序回答的问卷。访谈每一轮只使用一个开放问题；老人可以自由讲、换题、暂停或结束。算法只根据老人明确说过的内容提出下一步候选，不替老人补写事实。

## 3. 主题如何驱动访谈

1. **入口**：日常聊天不会自动进入 T1～T8。老人点击“聊往事”，或在 AI 邀请后明确同意，才建立正式访谈状态。
2. **选题**：优先使用老人自己点名或正在讲的线索；没有明确线索时，才从当前主题的首问中选一个低负担问题。模型可以提出候选主题，但不能直接切换、结束或写入 Memory。
3. **追问**：每次只追一个缺口，例如人物、时间、地点、场景、物件或这件事对老人的意义。追问的价值是补足故事，不是把所有字段问满。
4. **自然停顿**：达到当前线索的合理深度后，用自然句把选择权交还给老人，例如“这段经历先停在这里也可以。您还愿意继续讲吗，还是今天先到这里？”避免“收住精力”等老人不易理解的表达。
5. **接续**：暂停或下次继续时，只使用已经有来源的 `resumeHint`，例如“继续讲纺织厂第一次上夜班的经历”，不凭空补年份、人物或情绪。
6. **完成**：一个主题达到“至少一个直接来源 + 一个时间/地点/事件锚点”即可标记为可用；有关系、场景、物件、意义或变化等上下文时标记为丰富。老人说跳过、暂停或结束时，主题按本人意愿记录，不算算法失败。

## 4. 与 Memory 和成文的关系

访谈算法输出的是结构化的主题决策和候选线索，不直接写入权威 Memory。Memory 层再根据原话、来源、敏感性、确认状态和用途决定：

- 原始音频和最终转写作为来源证据保存；中间 ASR 不形成长期事实。
- 人物、时间、地点、事件、场景、关系、意义、变化和物件作为可检索维度。
- 普通低风险事实可以进入候选或按白名单自动整理；健康、财产、家庭冲突、隐私和老人明确限制的内容必须提高确认级别。
- 故事草稿只使用已允许的来源片段；不得因为主题名称或模型推断补写未说过的细节。
- 成文可以按主题拆成一篇或多张故事卡，保留“来源于哪次访谈、哪些原话、哪些是整理语句”的追溯信息。

## 5. 对算法实现的映射

| 产品概念 | 当前算法字段/模块 | 作用 |
| --- | --- | --- |
| 主题目录 | `InterviewProgram.topics` | 描述可选主题，不代表强制顺序 |
| 当前主题 | `PlanState.currentTopicId`、`currentTopic` | 约束本轮追问范围 |
| 已覆盖线索 | `TopicLedgerEvaluationState.coveredFacets` | 判断是否已有足够内容，避免重复追问 |
| 接续点 | `resumeHint` | 为下次访谈提供可验证入口 |
| 老人意愿 | `TopicUserDirection`、`ElderDirection` | 继续、换题、跳过、暂停和结束 |
| 下一步候选 | `SemanticTurnProposal` / `InterviewPolicy` | LLM 提议，可信策略层执行 |
| 权威保存 | `Memory` / `CanonicalMemory`（后续正式持久化） | 访谈层不越权写入 |
