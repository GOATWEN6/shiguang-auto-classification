## 结论

从本次成本账本启用后，服务会把每一次 provider 预留绑定到三个维度：

| 维度 | 展示方式 | 作用 |
|---|---|---|
| IP | 16 位脱敏指纹 | 判断同一来源在不同会话之间的累计消耗；不保存明文 IP |
| 会话 | 不可逆的短标签 | 区分重新开始后的不同会话 |
| 轮次 | 会话快照的 `turnCount + 1` | 区分同一会话中的第几轮 |

每次真实 provider 调用在调用前先写入账本，所以超时、失败和自动重试也会计入预留上限。当前豆包账单仍为 `PENDING`，因此 `actualCostCny` 暂时为 `null`；表中的 `reservedCny` 是调用前预留的上限，不是最终账单。
