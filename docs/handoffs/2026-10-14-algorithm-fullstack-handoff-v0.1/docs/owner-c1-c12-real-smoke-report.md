本记录把算法工作台的真实 HTTP 模型调用、暂停/恢复与换题修复放在同一条证据链中。记录中的“完成”只表示接口完成了本轮调用；追问质量、Memory 是否准确、故事和画像是否可用、声音是否自然，仍需要负责人在工作台人工体验后判断。

测试使用固定虚构身份和虚构经历，没有录入真实老人资料。算法服务使用豆包文本模型、ASR 和 TTS，运行状态为 `REAL_INTERNAL`，`CanonicalMemory` 正式持久化保持关闭。

### 初始运行暴露的两个工程问题

1. 暂停后的输入在 `session-store.openTurn()` 和 `TurnOrchestrator.requireUsableSession()` 被 ACTIVE 门禁提前拒绝，InterviewPolicy 没有机会判断“继续”。
2. “这段先聊到这里，我们说说后来……”没有进入显式换题识别，追问深度达到上限时被当作“是否继续当前线索”。

## 5. 修复内容

- `session-store.openTurn()` 允许 `PAUSED` 会话打开下一轮，让可信策略层判断是否继续；`RECOVERING` 和 `ENDED` 仍被阻断。
- `TurnOrchestrator.requireUsableSession()` 同步允许 `PAUSED` 进入策略判断。
- InterviewPolicy 增加暂停态无继续信号的保持分支，明确提示“说继续”后才恢复。
- 将策略返回的 `sessionStatus=ACTIVE/PAUSED/...` 映射到受信任的会话状态补丁，确保明确继续真正把会话从 `PAUSED` 改回 `ACTIVE`。
- 扩展自然换题表达识别，并保留新话题“后来在阳台种花”的来源与状态。
- 补充组合层回归测试：暂停态非继续保持暂停、明确继续恢复、自然换题进入 `SWITCH_TOPIC`。

## 6. 当前可下的结论

可以确认：暂停/继续和自然换题的 HTTP 算法链路已经在新 build 上完成定向真实复验，服务端策略、TTS 取消规则、Memory 候选边界和 `CanonicalMemory` 关闭状态均符合本阶段设计。

还不能确认：真人麦克风 ASR、真实扬声器播放时序、物理播放中的打断感受、故事草稿和画像草稿的内容质量。初始 C8 因暂停态阻塞未执行，后续需要在工作台开启一个新的活动会话单独体验故事和画像；这不需要重跑整批 C1～C12。
