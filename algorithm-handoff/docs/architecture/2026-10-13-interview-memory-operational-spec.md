## 1. 本版已经确认的四项组合

| 决策 | 当前采用方式 | 直接含义 |
|---|---|---|
| 访谈方向 | 1C：双通道自适应 | 默认跟随老人讲述；只有在老人需要、主动要求或自然停顿时，才提供少量主题选择 |
| Memory 保存 | 2A+B+D：低风险白名单自动保存 + 普通重要内容批量确认 + 高风险强确认/会话保留 | 不要求老人确认每句话，也不允许模型自由写入长期权威记忆 |
| Memory 检索 | 3D：R0—R3 渐进检索 | 先取当前最小必要信息，确有需要并且有授权才逐层扩大 |
| 访谈完成 | 4D：多信号组合 | 前台由老人意愿和自然停顿决定，后台用主题账本评估完整度，时长/轮数只作资源上限 |

这四项是当前设计基线。maxMinutes、maxQuestions、maxFollowUpDepth 等具体数值目前只作为首轮实验默认值，等内部成年人基线和负责人评审后再冻结，不能提前宣称为老人体验结论。

### 1.1 不变的权威边界

~~~text
原始音频/原始转写
    ↓
Evidence（带来源的证据）
    ↓
MemoryCandidate（模型提出的候选）
    ↓
确定性 Memory Policy Gate
    ↓
CanonicalMemory（业务当前可用的权威记录）
    ↓
按用途、权限和等级检索
    ↓
故事、画像、时间线、配图等派生视图
~~~

- InterviewPolicy 只能决定当前轮允许的动作和问题形态，不能直接写 CanonicalMemory。
- LLM 只能表达已经批准的动作，不能自行改变主题、权限、保存或删除。
- 故事、画像和图片是可重建视图，不能反过来覆盖 Evidence 或把推断变成事实。
- 用户纠正产生新版本或权限变化，不能静默覆盖原始依据。

## 2. 访谈主题账本

### 2.1 主题账本解决什么问题

主题账本不是给老人看的任务清单，而是后台的连续状态。它同时解决四个问题：

1. 当前正在讲哪条线索，避免每轮重新猜测；
2. 哪些内容已经达到“可用”，哪些只是提到过；
3. 老人跳题、暂停、拒绝或下次继续时，保留正确接续点；
4. 后台可以知道内容覆盖情况，但不会为了补齐字段强迫老人继续回答。

因此，“主题被记录”不等于“这段已经完成”，“没有覆盖”也不等于“本次访谈失败”。

### 2.2 主题与维度的分工

主题表示“要不要围绕什么谈”，维度表示“这段经历里已经有哪类信息”。二者不能混成一张问题表。

#### 基础维度

| 维度 | 要回答的不是固定问题，而是确认是否出现过 |
|---|---|
| 人物 | 谁参与、谁被提到；人物身份必须来自老人表达或明确来源 |
| 时间 | 年份、年龄、人生阶段或相对时间；不确定时保留不确定性 |
| 地点 | 城市、单位、家中、学校等；不强求精确地址 |
| 事件 | 发生了什么，做了什么，结果是什么 |
| 场景 | 当时的环境、物件、动作、声音或生活细节 |

#### 补充维度

| 维度 | 使用边界 |
|---|---|
| 关系 | 与谁的关系以及关系变化；不能从称谓自动推断亲属关系 |
| 意义与感受 | 只记录老人自己表达的意义、感受和评价，不把模型猜测当情绪事实 |
| 选择与变化 | 做过什么决定、后来发生了什么变化；必须有来源 |
| 影响与后续 | 对生活、家庭或工作的影响；不把“可能造成”写成事实 |
| 物件与材料 | 老物件、照片、信件、作品等；图片说明和物件本身分开保存 |
| 不确定性与禁谈 | “记不清”“不想说”“以后再谈”本身也是状态，不是缺失 |

#### 可用段落的最低要求

一段经历达到 USABLE 不要求所有维度齐全。最低要求是：

- 有一个老人认可或直接表达的经历/事实；
- 至少有一个时间、地点或其他清晰锚点；
- 有可追溯的原始证据；
- 没有未处理的关键人物/时间冲突；
- 老人可以在此处结束，不需要为了补字段再回答。

意义与感受、更多场景细节和后续影响可以让段落达到 RICH，但不是强制完成条件。

### 2.3 首版主题目录

目录是可选候选，不是所有老人都必须按顺序经过的阶段。

| topicId 示例 | 主题 | 适用目标 | 默认方式 |
|---|---|---|---|
| life-event | 一次具体经历 | 人生回忆、故事草稿 | 跟随老人当前线索 |
| life-period | 一段人生阶段 | 系统整理人生 | 需要老人选择或同意 |
| work-and-study | 学业与工作 | 人生回忆、家庭了解 | 只有相关线索出现才展开 |
| family-and-relationship | 家庭与重要关系 | 家庭故事、关系梳理 | 敏感关系最小必要检索 |
| place-and-home | 老家、迁居与常去地点 | 时间线、地点故事 | 不要求精确地址 |
| objects-and-photos | 老物件、照片和作品 | 故事/图文生成 | 以用户选择的材料为入口 |
| turning-points | 重要转折和选择 | 结构化访谈 | 需避免暗示“必须有重大转折” |
| meaning-and-reflection | 这段经历的意义 | 故事收束 | 只在老人愿意谈时询问 |
| follow-up | 上次未完成线索 | 跨会话接续 | 默认给老人继续/换题/结束选择 |

### 2.4 账本状态

当前运行时代码已有 OPEN / COVERED / SKIPPED / DEFERRED / BLOCKED。以下是更细的业务含义，暂时保持接口兼容。

| 业务状态 | 当前接口映射 | 解释 |
|---|---|---|
| UNSEEN | 没有该主题条目 | 本次目标中还没有接触 |
| OPEN | OPEN | 已出现线索或正在处理，有一个或多个待接续点 |
| IN_PROGRESS | OPEN + openLeadIds 非空 | 已经有内容，但还没达到可用段落 |
| USABLE | COVERED + completionReason=MINIMUM_USABLE | 已达到最低可用标准 |
| RICH | COVERED + qualityLevel=RICH | 有额外场景、意义或后续影响；不是必须 |
| DEFERRED | DEFERRED | 老人或系统决定以后再谈 |
| SKIPPED_BY_ELDER | SKIPPED | 老人明确跳过；本次不再主动追问 |
| BLOCKED | BLOCKED | 权限、敏感性、冲突或安全条件阻止继续 |
| NOT_APPLICABLE | BLOCKED + reason=NOT_APPLICABLE | 当前目标不需要该主题，不应显示成缺失 |

账本条目建议包含以下字段：

~~~ts
type TopicLedgerEntryV01 = {
  topicId: string;
  parentTopicId: string | null;
  topicType:
    | 'LIFE_EVENT'
    | 'LIFE_PERIOD'
    | 'RELATIONSHIP'
    | 'PLACE'
    | 'OBJECT'
    | 'MEANING'
    | 'FOLLOW_UP';
  status: 'OPEN' | 'COVERED' | 'SKIPPED' | 'DEFERRED' | 'BLOCKED';
  scope: 'CURRENT_TURN' | 'CURRENT_SESSION' | 'FUTURE_SESSIONS';
  scopeSessionEpoch: string;
  scopeTurnId: string | null;

  coveredFacets: Array<
    'PERSON' | 'TIME' | 'PLACE' | 'EVENT' | 'SCENE'
    | 'RELATIONSHIP' | 'MEANING' | 'CHANGE' | 'OBJECT'
  >;
  openLeadIds: string[];
  sourceRefs: string[];
  lastUserDirection:
    | 'CONTINUE'
    | 'SWITCH_TOPIC'
    | 'SKIP'
    | 'PAUSE'
    | 'END'
    | 'NONE';
  questionCount: number;
  followUpDepth: number;
  burdenLevel: 'LOW' | 'MEDIUM' | 'HIGH';
  uncertaintyLevel: 'LOW' | 'MEDIUM' | 'HIGH';
  completionReason:
    | 'MINIMUM_USABLE'
    | 'RICH_CONTEXT'
    | 'USER_ENDED'
    | 'USER_SKIPPED'
    | 'DEFERRED_BY_USER'
    | 'BLOCKED_BY_POLICY'
    | 'NOT_APPLICABLE'
    | null;
  resumeHint: string | null;
  planVersion: number;
  authorizationVersion: string;
  updatedAt: string;
};
~~~

说明：

- coveredFacets 是后台评估，不是要求模型逐项盘问；
- sourceRefs 只指向证据，不直接复制一段模型总结；
- resumeHint 必须是可验证的接续线索，例如“继续讲纺织厂里第一次当班的经历”，不能写成模型编造的结论；
- followUpDepth 记录围绕同一线索连续追问的深度，防止无尽追问；
- burdenLevel 和 uncertaintyLevel 不是认知诊断，不得与认知干预检测混用。

### 2.5 状态转移

| 触发 | 状态变化 | 是否前台告知 |
|---|---|---|
| 老人主动提到新线索 | UNSEEN → OPEN | 不显示内部状态 |
| 当前经历满足最低可用标准 | OPEN → COVERED/USABLE | 可在访谈结束后摘要展示 |
| 老人明确说“以后再说” | OPEN → DEFERRED | 告知可下次继续，但不强留 |
| 老人明确不想谈 | OPEN → SKIPPED | 尊重，不再主动追问 |
| 权限或敏感性阻止继续 | OPEN → BLOCKED | 只给简短、可理解的说明 |
| 本轮形成更多来源和意义 | USABLE → RICH | 只有老人查看整理结果时展示 |
| 老人换题 | 当前主题保留为 OPEN/USABLE，新主题进入 OPEN | 询问是否以后接着原线索 |
| 会话结束 | CURRENT_TURN 失效；CURRENT_SESSION 按授权处理 | 不把内部状态叫“未完成” |

### 2.6 主题选择和提问顺序

候选主题的优先级固定为：

~~~text
老人本轮明确方向
> 当前正在讲的连续线索
> 老人主动选择的主题
> 自然出现但尚未收束的线索
> 对当前故事有帮助的缺失基础维度
> 低负担且容易回答的补充维度
~~~

以下因素不能单独提高主题优先级：

- 模型觉得“这个主题更有戏剧性”；
- 家属希望补充但老人没有同意；
- 画像里缺失某个字段；
- 系统想达到覆盖率；
- 为了生成图片而反向追问不存在的细节。

### 2.7 提问规则

1. 一次回复最多一个真正的问题。
2. 默认先回应老人已经说的内容，再提出一个可选择回答的追问。
3. 连续围绕同一线索追问两次后，优先给出“继续、换个方向、下次再谈”的选择；followUpDepth=2 是首轮实验默认值，后续由真实基线校准。
4. 老人自然停顿时使用可继续也可结束的表达，例如：“这段您还想继续讲吗？也可以先停在这里。”
5. 老人说“不知道讲什么”时提供不超过三个主题选项，不替老人选择。
6. 推断只能作为可纠正的开放提示，例如“听起来那段经历对您很重要，如果我理解不对您可以纠正我”；不能直接写成“这件事一定让您很骄傲”。
7. “我听清楚了”只在确实需要确认听到的内容时使用，不能作为每轮固定开场。
8. 不用主题账本向老人显示“还差几个维度”，避免把回忆变成填表。

## 3. Memory 自动保存白名单

### 3.1 白名单的原则

自动保存不是“模型说了就记”。只有满足以下条件，候选才可以进入 AUTO_WRITE：

1. 来源：老人本人直接表达，或老人明确纠正/确认；
2. 主体：明确是老人本人，不是家人、朋友或模型推测；
3. 敏感性：S0 低敏感；
4. 类别：属于本节白名单；
5. 冲突：与当前权威记录没有未处理冲突；
6. 用途：只用于已经授权的用途，不扩大可见范围；
7. 可逆：老人可以快速撤回或纠正；
8. 可审计：保留原始证据、版本、策略版本和写入原因。

策略标识：

~~~text
policyVersion = sgx-memory-auto-save-whitelist-v0.1
~~~

模型不能通过输出字段把一个候选标成“白名单”。白名单由确定性分类器和 Policy Gate 判断。

### 3.2 首版允许自动保存的类别

| 类别 | 可以自动保存的例子 | 必须满足的限制 |
|---|---|---|
| 称呼和互动偏好 | “请叫我王奶奶”“我喜欢您说慢一点” | 仅作用于与老人交流；不推断性格 |
| 可访问性偏好 | “字幕要大一点”“我更习惯听语音” | 不涉及医学判断；可随时撤回 |
| 普通表达偏好 | “我喜欢听评弹”“我喜欢聊花草” | 不能把一次临时兴趣写成长期偏好；若不确定则会话保留 |
| 普通低风险习惯 | “我通常下午喝茶” | 不涉及用药、饮食禁忌、健康治疗、财务或安全 |
| 老人明确要求记住的低风险修正 | “刚才记错了，我不叫李阿姨，请叫我王阿姨” | 仍需通过主体、敏感性、冲突和证据门；高敏感内容不会因“记住”自动放行 |
| 普通使用设置 | “每次先给我文字，再读出来” | 只改变交互设置，不改变事实画像 |

### 3.3 不在自动保存白名单的类别

下列内容默认不能静默写入 CanonicalMemory：

- 健康、认知、情绪诊断、用药、饮食治疗和身体变化；
- 财产、收入、账号、证件、住址细节和其他凭据；
- 家庭冲突、创伤、虐待、法律纠纷和禁忌话题；
- 第三方身份、第三方健康和第三方隐私；
- 人物指认、照片中的身份和关系推断；
- 重要人生事件的完整事实链（可形成候选，默认批量确认）；
- “看起来”“可能”“应该是”等模型推断；
- 故事为了通顺而补写的时间、人物、动机、情绪或场景；
- 由系统观察得到的“回复变慢”“疑似记忆下降”等纵向判断；
- 仅因为家属、社区工作人员或模型提出的内容；
- 仅存在于生成图片中的新事实。

这些内容按情况进入 C2_BATCH_CONFIRM、C3_STRONG_CONFIRM、SOURCED_ONLY、SESSION_ONLY 或 BLOCKED/NO_MEMORY。

### 3.4 保存处置矩阵

| 候选类型 | 默认处置 | 老人看到的行为 |
|---|---|---|
| 白名单、低敏感、来源清楚 | AUTO_WRITE | 访谈后可在“最近记住”中查看、撤回 |
| 普通人生经历、重要事件 | C2_BATCH_CONFIRM | 自然收束后批量确认，不逐句打断 |
| 健康/认知/财产/家庭冲突 | C3_STRONG_CONFIRM | 明确说明用途和可见范围后单独确认 |
| 家属/社区提供但老人未确认 | SOURCED_ONLY | 只能标为“某人提供的线索”，不能当老人事实 |
| 当前对话临时目标、未证实内容 | SESSION_ONLY | 只在本次会话有效，不进入长期画像 |
| 凭据、越权、无法合法使用的内容 | NO_MEMORY 或 BLOCKED | 不保留业务内容，只留无内容审计记录 |

### 3.5 自动写入后的产品行为

自动保存必须配套三个轻量入口：

1. 最近记住了什么：展示简短内容、来源日期、用途和当前版本；
2. 立即撤回：撤回后马上阻断后续检索，并触发派生视图重算；
3. 纠正：生成新版本，保留原始证据和纠正来源，不静默覆写。

自动保存不等于永不过期。交互偏好和普通习惯可以有复核触发器，例如老人明确说“现在改了”、新证据冲突或一段时间未再使用。

### 3.6 白名单案例

| 输入 | 结果 | 原因 |
|---|---|---|
| “以后叫我王奶奶，说慢一点。” | AUTO_WRITE，拆成称呼和语速两条 | 本人直接表达，S0、可逆、用途明确 |
| “我退休前在纺织厂工作。” | C2_BATCH_CONFIRM | 重要人生经历，需要来源和时间确认 |
| “我最近吃不下饭，别告诉别人。” | C3_STRONG_CONFIRM 或 SESSION_ONLY | 健康/隐私高风险，不自动写普通长期记忆 |
| “我女儿说我年轻时在上海住过。” | SOURCED_ONLY | 家属来源，尚未成为老人确认事实 |
| “你回复慢，可能是认知下降。” | NO_MEMORY / 受保护观察通道 | 模型推断，不得写入画像或长期记忆 |
| “把这篇故事里缺的场景补成院子。” | 只作为故事草稿编辑，不能写 Memory | 生成内容不是事实证据 |

## 4. R0—R3 渐进检索等级

### 4.1 总原则

检索的目标是“当前任务足够用”，不是“把系统知道的都给模型”。每次检索都必须同时绑定：

~~~text
subjectId + familySpaceId + purpose + authorizationVersion
+ visibilityScope + asOf + retrievalLevel
~~~

返回的每一项都保留 recordId、版本、证据引用、时间范围、敏感级别和用途。模型不能只看到一段没有来源的摘要。

### 4.2 四个等级

| 等级 | 默认内容 | 允许触发 | 不允许做什么 |
|---|---|---|---|
| R0 当前轮 | 当前用户原话、当前会话已确认的上下文、当前轮主题状态 | 所有场景默认 | 不主动读取历史私密内容 |
| R1 稳定低风险 | 称呼、语速/字幕偏好、普通兴趣、已确认的低风险交互习惯 | 日常交流需要个性化时自动 | 不包含健康、家庭冲突、第三方和未确认人生事实 |
| R2 相关人生事件 | 与当前人物/事件/时间/地点直接相关的已授权 Life Memory、照片说明和访谈接续点 | 老人主动提到相关线索、选择故事材料、请求继续访谈 | 不把无关历史整体塞入当前上下文 |
| R3 受限敏感 | 健康、认知观察、家庭关系细节、私密照片、财产等受限内容 | 具体场景有明确授权、目的和可见范围 | 不得作为日常聊天默认上下文；不得因模型“觉得有帮助”自行升级 |

### 4.3 场景默认等级

| 场景 | 默认起点 | 允许扩大到 | 扩大前的条件 |
|---|---|---|---|
| 日常聊天 | R0 | R1；老人明确提起相关往事时 R2 | 相关性明确；R3 不默认 |
| 正式访谈 | R0 | R1、与当前主题直接相关的 R2 | 老人同意正式访谈；敏感主题另行授权 |
| 故事草稿 | 当前访谈证据 + 用户选择材料 | R2；R3 仅在用户明确选择并授权时 | 明确文章用途、可见范围和引用材料 |
| 基础画像草稿 | R0 + 已确认 R1 | 经过确认的 R2 主题摘要 | 不把健康、认知和关系推断混入普通画像 |
| 家庭共创 | 用户选中的故事/照片和授权协作者信息 | 指定范围的 R2/R3 | 明确参与者身份、用途和分享范围 |
| 认知观察/干预评估 | 独立受保护通道 | 仅取被授权的观察信号 | 不把观察结果回灌普通聊天或普通画像 |

### 4.4 逐层扩大规则

允许扩大检索的信号：

- 老人明确提到某段往事、人物、地点或照片；
- 老人选择“继续上次那段”；
- 老人明确要求“帮我写成故事/整理一下”；
- 当前任务缺少完成用户指定输出所必需的已授权材料；
- 经过产品明确设计的家庭共创授权。

不能触发扩大检索的信号：

- 模型想让回答“更完整”；
- 画像存在空白字段；
- 家属希望了解更多但老人没有授权；
- 当前主题与敏感历史只有模糊相似；
- 为了生成图片而猜测老人过去的场景。

### 4.5 首轮实验预算（暂定）

下列数值用于控制真实模型成本和上下文污染，不是永久产品阈值：

- R0：只取当前轮必要 Evidence；
- R1：最多 3 条最相关的稳定低风险记录；
- R2：最多 8 条与当前主题直接相关的记录/证据片段；
- R3：默认 0 条；只有明确选定的记录才进入，首轮最多 3 条；
- 每次扩大都记录 retrievalExpansionReason 和授权快照。

如果评测发现 R1/R2 过少或过多，再根据真实基线调整；不得直接把“更多记录”当成更高质量。

## 5. 访谈完成标准

### 5.1 四种“完成”必须分开

| 层级 | 含义 | 是否决定是否继续问 |
|---|---|---|
| 轮次完成 | 当前输入已处理，回复、TTS 和候选任务状态明确 | 是，决定下一轮是否可开始 |
| 主题完成 | 这条经历达到 USABLE 或 RICH，或老人明确跳过/延期 | 只提供建议，不强迫继续 |
| 会话完成 | 老人结束、自然停顿后选择停止、资源上限或安全条件触发 | 是，结束当前会话 |
| 计划覆盖 | 后台统计本次/多次会话覆盖了哪些主题 | 不单独决定结束 |

### 5.2 轮次完成

一轮满足以下条件才算完成：

- 已接收 final 文本，或明确记录 ASR/输入失败；
- InterviewPolicy 给出唯一允许的下一步；
- 若有问题，最多一个且通过输出校验；
- 旧 generation 已取消或确认不会迟到提交；
- TTS 成功、降级或错误状态已展示；
- Memory 候选异步任务有明确的 accepted/rejected/session_only/pending 状态；pending 不阻塞老人进入下一轮；
- 诊断日志包含 turnId、policyVersion、directionPlanId、retrievalLevel、memoryDecision。

### 5.3 主题达到 USABLE

以下条件全部满足：

1. 老人直接表达或明确确认了一个经历/事实；
2. 至少有一个人物、时间、地点、事件或场景锚点；
3. Evidence 引用可追溯；
4. 没有关键人物/时间冲突，或冲突已标为待确认；
5. 老人没有表示拒绝、疲劳或不想保存；
6. 已经可以生成“只根据证据”的简短段落；
7. 后续追问不会明显增加价值，或者老人愿意在此停下。

### 5.4 主题达到 RICH

在 USABLE 之上，至少多出一类真实来源的上下文：

- 具体场景/物件；
- 人物关系或关系变化；
- 选择、变化或后续影响；
- 老人自己表达的意义或感受；
- 能够支持文章结构的多个时间/地点锚点。

RICH 是故事草稿的质量提示，不是要求老人继续回答的理由。情绪和意义必须来自老人表达，不能由模型补写。

### 5.5 会话完成

满足任一条件即可结束：

- 老人明确说结束、暂停、不想继续或要求换题；
- 自然停顿后，老人选择“不继续”；
- 达到资源上限（首轮实验默认 20 分钟 / 12 个提问，仅作保护阈值）；
- 权限、安全或模型状态无法继续，需要安全收束；
- 输入连续失败，已给出可恢复方式。

会话结束时必须：

1. 给老人简短收束，不说“访谈不完整”；
2. 保存可继续的 resumeHint，前提是老人允许保存；
3. 将普通重要候选放入批量确认，而不是自动写入；
4. 将敏感内容留在受保护状态；
5. 展示本次整理了什么、暂未保存什么；
6. 允许老人删除本次会话内容。

### 5.6 计划覆盖只做后台指标

每个主题统计：

~~~text
UNSEEN / TOUCHED / USABLE / RICH / DEFERRED
/ SKIPPED_BY_ELDER / BLOCKED / NOT_APPLICABLE
~~~

首轮不使用“覆盖率达到多少才结束”。覆盖率用于：

- 发现长期遗漏；
- 选择下次可选主题；
- 比较不同策略的访谈质量；
- 帮助团队评审故事是否缺少关键来源。

### 5.7 质量评分维度

每轮或每段由算法工程师、产品/内容团队和康养专家分别评分；三方意见不能互相覆盖。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 追问价值 | 无关、重复或引导错误 | 有些相关但收益有限 | 明确帮助老人继续或收束 |
| 来源依据 | 出现无依据事实 | 大致有依据但需核对 | 每个关键点可追溯 |
| 非诱导性 | 暗示答案或替老人下结论 | 有轻微暗示 | 开放、可纠正、允许拒答 |
| 老人控制 | 打断、强迫或忽略结束 | 基本可控制 | 随时可停、换题、撤回 |
| 负担与等待 | 明显疲劳、重复等待 | 可接受但有摩擦 | 节奏自然、等待有反馈 |
| Memory 可用性 | 错误/越权/无法使用 | 需要较多修正 | 用途明确、来源完整、可撤回 |
| 草稿可用性 | 添加事实或严重改写 | 需编辑 | 平白温情、适度规整、忠于原话 |

底线门禁：

- 隐私、权限、来源错误：立即不通过；
- 把模型推断当事实：立即不通过；
- 忽略老人结束/撤回：立即不通过；
- 质量阈值：先完成小规模内部 baseline，再冻结。

## 6. 与现有代码和接口的落地关系

### 6.0 这四个 TS 模块不是完整的 AI 算法

本文件配套的四个 TS 模块是**可执行的确定性边界层**，不是把所有会话场景硬编码成规则，也不是取消大模型：

| 层 | 主要职责 | 是否允许大模型参与 |
|---|---|---|
| 语音与输入层 | VAD、打断、ASR、原始转写和短文本整理 | 模型可参与语音识别；原始音频和原始转写必须保留 |
| AI 语义层 | 识别老人意图、主题、人物/时间/地点/事件线索、候选 Memory、相关检索查询和自然语言表达 | **必须参与**；输出结构化候选、来源片段和不确定性 |
| 确定性策略层 | 主题状态、敏感性、权限、检索等级、保存处置、结束条件和失败降级 | **不能被模型绕过**；只接受结构化输入并给出可审计决定 |
| LLM Realizer | 把已批准的动作表达成平白、温情、一次一问的回复 | 可以参与表达，但不能新增动作、事实、权限或保存命令 |
| CanonicalMemory / 派生层 | 权威写入、检索、故事、画像和图片 | 模型可以提出候选或草稿；最终写入和来源校验由策略/后端完成 |

因此，四个 TS 模块的正确定位是：

```text
AI 负责理解开放语言并提出候选
→ TS 规则负责验证、限制和记录
→ AI 只能表达已批准的下一步
→ Memory/后端再次执行权限和版本门
```

如果只有 TS 规则，系统无法覆盖老人多样的说法；如果只有大模型，系统会出现误存、越权检索、把推断说成事实和无法稳定复现的问题。首版采用两者组合，是为了让“开放理解”与“不可越过的边界”分开。

### 6.1 已有能力可以继续复用

- InterviewProgram → SessionPlan → PlanState → DirectionPlan 的最小合同；
- OPEN/COVERED/SKIPPED/DEFERRED/BLOCKED 主题状态；
- 当前轮老人方向证据、最多三个候选主题和权限边界；
- M2 确定性 Memory Policy；
- Evidence、MemoryCandidate、Reference Store 和 CanonicalMemory Repository 端口；
- 现有的 sourceRefs、authorizationVersion、policyVersion 和版本纠正机制。

### 6.2 已新增的纯规则模块及待接线位置

实现顺序建议为：

1. topic-ledger-evaluator-v0.1（已实现，待接入 Session 状态）
   - 根据 Evidence 和用户方向更新 coveredFacets、openLeadIds、完成原因；
   - 只更新状态，不产生自然语言。
2. memory-autosave-whitelist-v0.1（已实现，待接入 Memory orchestration）
   - 确定性判断白名单类别和八项写入门；
   - 复用现有 evaluateMemoryPolicy，不绕过 S2、凭据和治理阻断。
3. memory-retrieval-levels-v0.1（已实现，待接入检索门）
   - 把场景用途映射到 R0—R3；
   - 检查 purpose、visibilityScope、authorizationVersion；
   - 返回带来源和版本的检索包。
4. interview-completion-evaluator-v0.1（已实现，待接入 InterviewPolicy）
   - 区分轮次、主题、会话和计划覆盖；
   - 输出 continue / offer_choices / pause / end / review，不直接生成话术。
5. InterviewPolicy 接线（下一阶段）
   - 策略先于 LLM Realizer；
   - 先通过测试，再接真实模型；
   - 失败只降级到受控 fallback，不自动放宽权限。

### 6.3 AI 语义合同（已建立候选，shadow 前需评审）

四个规则模块不能直接读取一段自然语言猜测。AI 语义层至少要输出以下结构化字段：

~~~ts
type SemanticTurnProposal = {
  userIntent:
    | 'CONTINUE_TOPIC'
    | 'SWITCH_TOPIC'
    | 'SKIP_TOPIC'
    | 'PAUSE'
    | 'END'
    | 'ASK_FOR_HELP'
    | 'ORDINARY_CHAT'
    | 'UNKNOWN';
  topicId: string | null;
  observedFacets: Array<'PERSON' | 'TIME' | 'PLACE' | 'EVENT' | 'SCENE'
    | 'RELATIONSHIP' | 'MEANING' | 'CHANGE' | 'OBJECT'>;
  sourceSpans: Array<{ evidenceRef: string; quote: string }>;
  memoryCandidates: Array<{
    claim: string;
    contentType: string;
    sensitivityHint: 'S0' | 'S1' | 'S2' | 'UNKNOWN';
    sourceEvidenceRefs: string[];
  }>;
  relatedMemoryQuery: string | null;
  userUncertainty: 'LOW' | 'MEDIUM' | 'HIGH' | 'UNKNOWN';
  needsClarification: boolean;
};
~~~

对应实现：[SemanticTurnProposal 校验器](../../src/lib/algorithm-service/semantic-turn-proposal.ts)。当前版本是候选合同，必须先在 shadow 场景中观察真实模型输出，再决定是否升级为强制 enforcement 合同。

合同要求：

- 每个 Memory 候选必须引用当前 Evidence 的连续原文片段；无法引用时只能返回候选无效或空候选。
- AI 可以返回 UNKNOWN，不能为了填满字段而猜测。
- `sensitivityHint` 只是模型提示，最终敏感性由确定性政策重新判断。
- `userIntent` 只是意图候选，老人当前轮的明确 UI/语音证据优先于模型猜测。
- `relatedMemoryQuery` 不能直接升级检索等级，必须经过 R0—R3 检索门。
- 语义层失败时，当前轮仍可只用原话继续，Memory 进入 `SESSION_ONLY` 或 `pending`，不能让用户无限等待。

### 6.4 不在本轮直接做的事情

- 不打开正式 canonicalWriteCapability；
- 不新增数据库迁移；
- 不把现有旧 MemoryCard 静默迁移为 CanonicalMemory；
- 不因主题账本而强制老人按人生阶段顺序回答；
- 不把 R3 敏感内容加入普通聊天；
- 不用生成故事或图片反推事实；
- 不进行真人老人数据测试，直到规则和内部成年人体验通过质量门禁。

## 7. 固定验证案例

实现上述规则后，至少要有以下可重复案例：

| 案例 | 预期 |
|---|---|
| 老人主动讲纺织厂工作，随后换到老家 | 纺织厂主题保留接续点，老家成为当前主题，不把前者标为失败 |
| 老人说“不知道讲什么” | 提供最多三个主题选择，不替老人选 |
| 老人自然停顿并说“先这样吧” | 会话结束；不继续追问；普通候选进入批量确认 |
| 老人说“以后叫我王奶奶，说慢一点” | 两条低风险白名单候选可自动保存，均带原文证据和撤回入口 |
| 老人说“最近吃不下饭” | 不进入普通自动保存；按高敏感或会话保留处理 |
| 家属说“她年轻时在上海住过” | 仅作家属来源线索，不能当老人事实 |
| 故事草稿补写“院子里阳光很好” | 如果原始材料没有该内容，只能标为待用户补充，不能写入 Memory |
| 日常聊天问“我喜欢什么” | R0 不足时最多扩大到 R1；不读取健康、家庭冲突或完整画像 |
| 正式访谈明确继续上次纺织厂经历 | 允许 R2 取相关已授权记录；不读取无关家庭隐私 |
| 家庭共创选择一张照片 | 只读取该照片及已授权说明；人物身份不因模型相似度自动确认 |
| 老人撤回一条记忆 | 立即从检索结果中移除；故事/画像标记需重算；保留无内容审计记录 |
| 旧 TTS 在用户打断后迟到 | 旧 generation 不得播放或提交 Memory 候选 |

## 8. 版本、日志和验收要求

每次主题、保存或检索决策至少记录：

~~~text
algorithmBuildId
policyVersion
programVersion
sessionPlanId
directionPlanId
turnId
topicLedgerVersion
retrievalLevel
retrievalExpansionReason
candidateId / recordId
sourceEvidenceRefs
authorizationVersion
decisionDisposition
completionReason
~~~

日志分三层：

1. 用户可见摘要：本次记住了什么、哪些暂不保存、是否可以撤回；
2. 团队评审日志：输入、AI 回复、追问判断、Memory 候选、检索层级、完成原因；
3. 无内容审计日志：撤回、删除、权限拒绝、策略版本、错误码；不复制原始敏感内容。

验收不以“模型返回了文本”作为完成条件，而以以下组合判断：

~~~text
接口合同通过
+ 来源与权限门通过
+ 访谈状态可恢复
+ 追问和结束行为符合组合规则
+ Memory 处置正确
+ 检索等级不越权
+ 派生故事/画像不新增事实
+ 失败可解释且不让用户无限等待
~~~

## 9. 本版结论与下一步

本版已经把负责人确认的四项组合转成了可执行规则，但仍保留两类可校准项：

- 访谈时长、提问数和连续追问深度的首轮默认值；
- R1/R2/R3 的实际检索数量和质量阈值。

下一步按以下顺序推进：

1. 把本文件中的四个纯规则模块写成类型和确定性测试；
2. 运行固定验证案例，确认与现有 direction-plan、M2 Policy 和 Reference Store 不冲突；
3. 更新团队阅读包，用产品语言解释“什么时候追问、什么时候记住、什么时候调用历史”；
4. 再做小规模真实模型定向验证；
5. 由算法负责人、产品/内容团队和康养专家分别评分；
6. 评分通过后再决定是否进入内部成年人真人访谈；
7. 正式 CanonicalMemory 持久化仍按独立 C2 门禁推进，不因本文件而提前打开生产写入。

本文件只冻结“如何决策”的边界，不把未经真人基线校准的数值包装成最终效果结论。
